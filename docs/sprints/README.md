# Resúmenes de sprint

Cada sprint cerrado crea `SPRINT-XX-SUMMARY.md` con:

- qué se construyó, en negocio y técnico;
- cómo verlo funcionar, con comandos copiables;
- criterios de aceptación ejecutados y resultado;
- decisiones/ADRs;
- asuntos abiertos y riesgos conocidos.

Los criterios concretos de cada sprint se toman del brief y de la aprobación del fundador.
Los asuntos aceptados para un sprint posterior deben quedar explícitos en el resumen y en
`OPEN_ISSUES.md`, con fecha o hito límite.
